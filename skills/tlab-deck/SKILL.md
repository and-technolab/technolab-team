# Презентации ТехноЛаба

Преврати материалы пользователя в презентацию с одной ясной мыслью на слайде. Поддерживай редактирование существующих дек и оформление готового содержания. Все необходимые правила и ресурсы находятся внутри этой папки.

## Подготовка

1. Прочитай [гайд стиля](references/style.md). Для нового содержания прочитай [правила текста](references/writing.md); для материалов об ИИ — [терминологию](references/terminology.md).
2. Определи аудиторию, задачу, объём и формат из запроса. Уточняй только то, что меняет результат и не следует из материалов. Для локальной правки сохрани остальное оформление и содержание.
3. Следуй явно выбранному формату. Если формат не задан, используй самодостаточную HTML-деку; добавь PDF, когда доступен браузерный экспорт. Для редактируемого PPTX или Google Slides примени тот же гайд через доступный инструмент презентаций. HTML-шаблон сам по себе не создаёт редактируемый PowerPoint.
4. Для новой HTML-деки скопируй [starter.html](assets/starter.html) в папку результата. Открой демонстрационные слайды как визуальный ориентир. Они показывают разные композиции, а не обязательную последовательность слайдов.

## Содержание и оформление

- Выбирай композицию под мысль: сопоставление, связь частей, последовательность, отдельный тезис. Новые композиции разрешены. Не своди все кадры к одинаковым карточкам.
- Строй утверждения, числа и примеры на материалах пользователя. Условный пример подпиши. Отсутствующее число не придумывай.
- Название может быть темой, вопросом или выводом — выбирай по назначению слайда.
- Используй параметры из гайда и шаблона: Unbounded, Onest, JetBrains Mono; белый, чернильный, тёмно-синий и латунь. В шаблоне шрифты и логотип встроены, интернет для показа не нужен.
- Автор и контакт берутся из задания. Если они не указаны, оставь подпись организации или убери персональную подпись. Не переноси автора из демонстрации.
- В HTML сохраняй холст 1280 × 720, масштабирование по обеим осям, навигацию с клавиатуры и режим печати. При добавлении слайда следуй структуре `<section class="slide">` и сохраняй уникальный `id`.
- Склей короткие слова через `&nbsp;` по [правилам типографики](references/typography.md). Для HTML в комплекте есть `scripts/typography.py`: команды `fix` и `check`.

## Проверка и выдача

Проверь весь результат в размере показа: загрузку шрифтов, переносы, видимость линий, наложения и обрезку. При редактировании сравни изменённые слайды с исходными. Отдельно проверь PDF: один слайд на страницу, фон, счётчики, подписи и отсутствие навигации.

Для HTML доступны воспроизводимые проверки и экспорт:

```bash
python3 <skill>/scripts/typography.py fix <deck.html>
python3 <skill>/scripts/typography.py check <deck.html>
npm install --prefix <skill> --ignore-scripts
npx --prefix <skill> playwright install chromium
node <skill>/scripts/render.mjs <deck.html> <output-directory>
```

`<skill>` — папка установленного `tlab-deck`. Выполняй команды только при наличии соответствующей среды. Если среда не позволяет запустить браузер, выдай доступный формат и явно укажи, что визуальная проверка или PDF-экспорт не выполнены.

`render.mjs` проверяет шрифты, выход текста за холст и переполнение блоков, сохраняет снимки и PDF. Это помощь для проверки, а не оценка качества композиции. Открой полученные изображения и проверь глазами. Подробности HTML и экспорта — в [references/html.md](references/html.md).

Отдай готовые файлы и кратко назови ограничения, влияющие на использование. Не добавляй в слайды служебные записи о генерации, проверках или устройстве скилла, если тема презентации этого не требует.
